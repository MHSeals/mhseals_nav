# Odometry startup YAML

`config/odometry_startup.yaml` owns robot-state publish frequency, MAVROS adapter velocity source and five uncertainty/age controls, and standalone/included EKF delay. Resolve package defaults, then explicitly selected `odometry_deployment_file`, then `odometry_startup_file`, then nonempty compatibility aliases. Each selected file must exist and every layer is validated before precedence. No implicit user layer was added. Returned `inputs` record absolute paths and SHA256 of actual bytes; these are requested startup settings, not live verification.

`resolve_odometry(package_file=None, deployment_file='', operator_file='', aliases=None, context='standalone')` returns immutable `.values`, `.inputs`, `.context`, selected `.delay`, and actual `.adapter_parameters`. Default package lookup uses ament installed share, independent of cwd. Launch args `ekf_startup_context=standalone|included` select defaults 0/6; odom defaults included, independent EKF defaults standalone. An explicit context can preserve sequencing when EKF is managed separately. Robot forwards all startup layers, aliases, and localization file selections to odom; odom forwards them to EKF. Empty aliases inherit YAML.
