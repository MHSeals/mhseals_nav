# Endpoint startup authority

`config/endpoint_startup.yaml` owns FCU endpoint selection, simulation endpoint, absolute serial fallback, common Unity bind IPv4/port, and per-context GCS/discovery/baud. Contexts standalone/full_robot retain CubeOrange if00 discovery and115200 baud; tui retains stable hinted-device discovery, unrepresented ttyACM/ttyUSB fallback and57600 baud. Discovery remains executable Python. Source extraction/equivalence tests use temporary directories; no device, socket or DNS operation is used for validation.

Migration: full_robot's historical `udp://127.0.0.1:14550` lacks libmavconn's required @. Owner explicitly approved changing its packaged default to `udp://@127.0.0.1:14550`, matching standalone. Explicit invalid operator values are rejected without normalization. Empty GCS URL disables forwarding, verified against2.16.0 mavros_node source. See endpoint-parser-evidence.md for exact version and source pins.

Precedence is package authority < explicit endpoint_deployment_file < explicit endpoint_startup_file < supplied compatibility aliases. Empty fcu_url, ros_ip and ros_port inherit; gcs_url uses `__inherit__` sentinel so explicit empty can disable. No implicit user layer or cwd search. Every selected file/layer validates independently. Relative selected file names follow explicit caller path semantics; authority lookup uses installed ament package share. All input paths become absolute and raw-byte SHA256 identities; aliases have separate immutable provenance. These describe requested inputs, not live transport state.

Public API: resolve_endpoints(package_file=None, deployment_file='', operator_file='', aliases=None, context='standalone') returns immutable .values/.inputs/.overrides/.context; .unity_parameters is string ROS_IP plus exact integer ROS_TCP_PORT; .mavros_parameters(sim, dev_root=Path('/dev')) returns (parameters, discovery_observation). A discovery observation describes only a local selected path/fallback, never connected hardware identity. No shared runtime dependency on mhseals_hardware was added; the fixed tui discovery helper reproduces its existing pure algorithm.

URL validation deliberately supports bounded libmavconn2.16.0 forms: absolute schemeless serial paths, serial/serial-hwfc absolute paths with optional positive int32 baud, udp/udp-b/udp-pb bind@remote, tcp/tcp-l hosts with optional1..65535 ports, optional ids query using parser uint8 representation. IPv4/hostname tokens are retained without DNS; URI bytes are never normalized. Exotic host token syntax outside this bounded grammar is explicitly unsupported. Unknown query text follows libmavconn's ignore behavior; validation does not claim transport success. Unity independently requires IPv4 literals and exact integer1..65535 listener ports. Booleans cannot be numeric ports/baud.

Robot puts a pure endpoint gate first among executable actions, before included launches can create children; odom validates its endpoint closure before nodes, and individual MAVROS/sensors factories validate again. Robot explicitly forwards common selections to odom/sensors. Topology, host DDS/network, camera settings, delivered transport behavior and runtime restart activation are outside scope. The testing counterpart must select context=tui, remove implicit TUI fcu_url injection, preserve only actual CLI overrides, and enforce coherent selections before process planning.
